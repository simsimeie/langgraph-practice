# 08. 멀티 에이전트 (Multi-Agent)

## 개요

복잡한 문제를 해결하기 위해 **여러 전문화된 에이전트**가 협력하는 아키텍처입니다.
각 에이전트는 특정 영역을 담당하고, 서로 통신하며 작업을 완수합니다.

## 왜 멀티 에이전트인가?

| 단일 에이전트 | 멀티 에이전트 |
|-------------|--------------|
| 하나의 LLM이 모든 작업 처리 | 전문화된 에이전트가 협력 |
| 컨텍스트 길이 한계 | 각 에이전트가 독립 컨텍스트 유지 |
| 단일 실패 지점 | 일부 실패해도 전체 시스템 계속 동작 |
| 품질 검증 어려움 | 에이전트 간 검증 가능 |

## 주요 멀티 에이전트 패턴

### 1. Supervisor 패턴
중앙 수퍼바이저가 작업을 분배하고 조율합니다.

```
사용자 요청
    │
    ▼
[수퍼바이저 에이전트]
    ├──▶ [연구원 에이전트]
    ├──▶ [코더 에이전트]
    └──▶ [검토자 에이전트]
         └──▶ [수퍼바이저]로 결과 보고
```

### 2. Handoff 패턴
에이전트가 작업을 다른 에이전트에게 직접 넘깁니다.

```
[에이전트 A] → (핸드오프) → [에이전트 B] → (핸드오프) → [에이전트 C]
```

### 3. Swarm 패턴
에이전트들이 동적으로 작업을 교환합니다. (LangGraph의 swarm 프리빌트 사용)
